# ЭТАП 6. Мастер-план проекта AURA (взгляд оркестратора)

Обновлено: 18.09.2026. Документ отвечает на три вопроса: **что мы делаем и где мы**, **чего не хватает** (данные, скиллы, инструменты), **как довести до публикации**.

---

## 1. Что это за проект (одна страница)

**Бизнес-цель:** сайт сети ювелирных салонов AURA в Московской области, который **торгует**, а не только красиво выглядит:
каталог с реальными товарами, ценами и наличием из 1С, оформление заказа на самовывоз из ближайшего салона, личный кабинет с бонусами и паспортами украшений.

**Три контура, которые уже существуют в проекте:**

| Контур | Путь | Что это | Состояние |
|---|---|---|---|
| **Дизайн-эталон** | `mockups/` | 21 страница: главная, каталог, карточка, свадьба, акции, салон, паспорт, сертификаты, отзывы, корзина, оформление, кабинет, доставка, возврат, гарантия, FAQ, о компании, контакты, правовая, карта сайта, 404 | Готов, опубликован на GitHub Pages, контраст 0 нарушений, 15/15 функциональных тестов |
| **Данные 1С (BizHub)** | внешний проект + выгрузка | Выгрузка «ЮТД 10.5»: 111 тыс. номенклатур, ~467 тыс. характеристик, ~642 тыс. бирок, продажи, остатки, карты лояльности. Обновление — ежедневно с флешки | Данные извлечены в `warehouse.db`; для сайта собрана витрина |
| **Сервер витрины** | `server/` | Python-API (`api.py`) + база витрины `data/site_catalog.db` (**14 147 моделей**, 9 салонов, цены, остатки по 7 городам) + приём заказов на самовывоз (`orders.json`, `orders.html`) | Работает локально на порту 8138; сайт `site/` (копия `mockups/` + `live.js`) подтягивает реальные данные |

**Что уже реально из 1С:** категории, названия, артикул, металл/проба, цена, наличие по городам, счётчики на главной, заказ на самовывоз с сохранением заявки.

**Чего нет:** фото товаров (в 1С их нет), розничные цены из регистра цен (сейчас цена последней продажи), клиенты/лояльность из 1С, обмен заказами с 1С, домен и аналитика.

## 2. Целевая архитектура (без покупки CMS)

```
выгрузка 1С (флешка, раз в сутки)
        │
        ▼
BizHub: warehouse.db  ──(build_catalog)──►  витрина site_catalog.db (только «полка для сайта»)
                                                   │
                                                   ▼
                                   API (Python/Node) — /catalog, /product, /salons, /order
                                                   │
                                                   ▼
                            сайт AURA (mockups → site + live.js): дизайн не переделывается
```

Принципы: дизайн-макет — эталон и не меняется; витрина содержит только то, что можно показывать (без телефонов клиентов и внутренних сумм); если выгрузки нет — сайт работает на предыдущих данных и пишет ошибку, но не ломается.

## 3. Уровни работ

| Уровень | Содержание | Статус |
|---|---|---|
| **1. Каталог-витрина** | Реальные товары, цены, наличие по салонам, фильтры, корзина → заказ на самовывоз, служебная страница заказов | Собрано на данных; нужно довести до продакшена (хостинг, домен, обновление по расписанию, фото) |
| **2. Клиенты и кабинет** | Вход по телефону → карта лояльности в 1С: бонусы, «мои покупки», цифровые паспорта украшений | Не начат; данные в выгрузке есть (карты, бонусы, чеки) |
| **3. Заказы в 1С** | Резерв/заказ/запись на примерку создаются в 1С и отслеживаются по статусам | Требует 1С-специалиста; пока сознательно отложено |
| **Медиа и контент** | Фото товаров, баннеры, видео, тексты | Фото — не начато (ключевая задача), баннеры — есть, видео — по желанию |

## 4. Ключевое решение, которое нужно принять: фото товаров

В 1С фото нет. В каталоге **14 147 моделей** — поштучная генерация невозможна по смыслу и цене (14 147 × 4–10 кредитов = 57–141 тыс. кредитов, $285–700), а главное — это будут выдуманные фото, а не реальные украшения.

**Предлагаемая стратегия — библиотека типовых снимков:**
1. Разобрать названия 1С на **типы изделий** (кольцо гладкое / с бриллиантом / печатка / обручальное; серьги-пусеты / кольца-конго / подвески; цепь венеция / бисмарк / якорное; браслет; крест; икона; посуда; часы и т.д.).
2. Сгенерировать через KIE **40–60 типовых снимков** в едином студийном стиле (белый фон, 1:1) — по ним каталог будет выглядеть цельно и честно («фото типовое, точный вид — в салоне»).
3. Когда появятся **реальные фото** — загружать их точечно: `recraft/remove-background` (1 кредит) приводит любой снимок к нашему белому фону, `topaz/image-upscale` тянет качество до 2K.
4. На карточках — пометка «Фото типовое», у моделей с реальными фото пометки нет.

**Бюджет библиотеки:** 40–60 изображений × 4 кредита (nano-banana-edit) = **160–240 кредитов (~$0.8–1.2)**. Сейчас на балансе ~790.

## 5. Медиа-конвейер KIE (что доступно на нашем ключе)

Полный инвентарь: `analysis/ЭТАП-6_kie-модели-и-скиллы.md` (выгрузка 206 моделей: `analysis/kie-модели-выгрузка.json`).

| Задача | Модель | Цена |
|---|---|---|
| Фото товара в студийном стиле | `gpt-image-2-image-to-image` (используем) / `google/nano-banana-edit` | 10 / **4 кредита** |
| Массовые черновые варианты | `z-image` | **0.8 кредита** |
| Убрать фон у любого фото | `recraft/remove-background` | **1 кредит** |
| Апскейл до 2K/4K | `topaz/image-upscale` / `recraft/crisp-upscale` | 10–20 / 0.5 |
| Баннеры и промо-сцены | `seedream/4.5`, `google/nano-banana`, `imagen4` | 4–8 кредитов |
| Видео (баннер, reels) | `bytedance/seedance-2-mini` | ~102 кредита за 5 сек |
| Озвучка / музыка | ElevenLabs / Suno | по тарифу |
| **Дизайн-ревью и тексты** | **`gpt-5-2` (vision, работает)** | ~0.16 кредита за экран |

Недоступны на ключе: `gemini-*`, `claude-*`, `grok-*` (ответы «no user can use» / «model is not supported»).

## 6. Скиллы: что есть и чего не хватает

### Есть
`ui-ux-pro-max` (дизайн-система, UX-правила) · `vision-skills` (локальный vision: кроп, палитра, пиксельный diff) · `generate-anything` (KIE: фото/видео/звук) · Ollama Qwen2.5-VL локально · собственные QA-скрипты в `_qa/` (контраст WCAG, функциональные тесты, аудит ссылок, скриншоты по CDP) · внешний ревьюер `gpt-5-2` через KIE.

### Не хватает (с приоритетом)
| Пробел | Зачем | Как закрываем |
|---|---|---|
| **ETL-слой «1С → витрина»** под фото и типами | без разбора названий на типы не будет библиотеки фото | доработать `catalog_build.py`: классификатор типов по названию (регекспы + справочник) |
| **Хостинг и деплой витрины** | сейчас API живёт только локально | аренда VPS/облака, Docker, автозапуск, домен + HTTPS, ежедневное обновление |
| **Schema.org / SEO для живого каталога** | 14 тыс. страниц товаров должны индексироваться | генерация `<script type="application/ld+json">` (Product/Offer/AggregateRating) в шаблонах |
| **Производительность каталога** | 14 тыс. позиций, фильтры, пагинация | серверная пагинация и индексы в SQLite, ленивые картинки, кэш |
| **Дизайн-токены в одном слое** | сейчас 3 слоя CSS конфликтуют | рефакторинг: `tokens.css` + семантика, чистка `aura.css`/`theme-sun.css` |
| **Полный a11y-прогон** | контраст уже 0 нарушений, но фокус/aria не проверены | axe-core через CDP + чеклист, фикс мега-меню и модалок |
| **Аналитика и цели** | без метрик нельзя оценить эффект | Яндекс.Метрика + события «В корзину», «Зарезервировать», «Позвонить» |
| **Визуальная регрессия** | правки дизайна ломают вёрстку незаметно | эталонные скриншоты + `vision_pixel_diff` в пайплайне |
| **CI** | сейчас публикация руками, ключи в temp-репозитории | GitHub Actions: сборка, проверки, деплой |

## 8. Что нужно от заказчика (блокирует финал)

1. **Данные:** реальные цены из регистра цен, фото (если есть у поставщиков), наличие на текущую дату.
2. **Контакты:** рабочий номер 8-800, точные адреса/телефоны/часы 7 городов (подтвердить, что Жуковского нет).
3. **Юридическое:** оферта, политика, реквизиты юрлица; согласование формулировок про скидки («до −80%»).
4. **Решения:** где хостить (VPS/облако), какой домен, нужен ли личный кабинет на этом этапе, нужны ли видео.
5. **Доступы:** ключи API (KIE, аналитика), права на публикацию, GitHub-токен перевыпустить.

## 9. Критерии готовности к публикации

- [ ] Каталог на реальных данных: 14 147 моделей, цены, наличие по 7 городам — на боевом хостинге.
- [ ] Фото: библиотека типов (40–60 снимков) подставлена по типам; реальные фото подгружаются по мере появления.
- [ ] Заказ на самовывоз работает и виден сотрудникам; клиенту приходит подтверждение.
- [ ] Дизайн: оценки внешнего ревью ≥ 8/10 по привлекательности и доверию на всех ключевых экранах.
- [ ] Контраст 0 нарушений, функциональные тесты 100%, Lighthouse ≥ 90/95.
- [ ] Schema.org (Product, Offer, LocalBusiness, BreadcrumbList) валиден.
- [ ] Обновление из 1С по расписанию, с журналом и безопасным откатом.
- [ ] Аналитика и цели настроены; домен с HTTPS; юридические тексты согласованы.

## 10. Ближайшие шаги (что делаю без ожидания)

1. **Классификатор типов изделий** по 14 147 названиям 1С (для библиотеки фото и для фильтров каталога).
2. **Библиотека типовых фото** через KIE (40–60 снимков, ~200 кредитов) + автоподстановка по типу.
3. **Топ-3 правки дизайна из ревью**: плотность карточки/витрины, разгрузка hero, «0-0-6» словами.
4. **Schema.org и Lighthouse** на живом каталоге.
5. **Рефакторинг токенов CSS** и подготовка CI-публикации.
