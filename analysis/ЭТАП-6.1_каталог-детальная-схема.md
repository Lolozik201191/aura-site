# ЭТАП 6.1. Уровень 1 — детальная схема «каталог-витрина» (на реальных данных)

> Что это: подробная схема того, что будет построено, с **живыми примерами из вашей выгрузки 1С**
> (товары, наличие по салонам), чтобы вы видели данные до старта работ.
> Границы Уровня 1: витрина-каталог + корзина + **заказ на самовывоз** (заявка салону).
> Без онлайн-оплаты, без создания документов в 1С. Фото товаров — позже.
> Работает пока на вашем ПК; архитектура сразу рассчитана на переезд на хостинг.

---

## 1. Что покажет сайт (главное)

Клиент открывает AURA.RU и видит настоящий каталог сети:

- категории: Кольца / Серьги / Браслеты / Колье / Подвески / Цепи (+ Свадьба: обручальные);
- у каждого товара: название, **золото 585 / серебро**, цена, «**В наличии: Раменское (13 шт), Ногинск (14 шт)…**»,
  кнопки «В корзину», «Зарезервировать в салоне»;
- фильтры: металл, проба, камень, цена, «только в наличии в моём городе»;
- корзина → оформление → **заказ на самовывоз из выбранного салона** (клиент оставляет телефон);
- заказ не «уходит в никуда»: он виден вам в разделе «Заказы» и дублируется (по желанию) письмом/Telegram.

Обновление: вставили флешку с выгрузкой → запустили ярлык → через ~30–60 минут сайт показывает
свежие цены и остатки. Если что-то пошло не так — сайт остаётся на старых данных, а вы получаете
запись об ошибке (тихо не ломается).

## 2. «Словарь» — как мы говорим о данных (по-простому)

| Термин | Что это | Откуда |
|---|---|---|
| **Бирка / партия** | Одно конкретное украшение в 1С (у каждой свой штрихкод, вес, цена, магазин) | 1С, сотни тысяч шт. |
| **Товар-модель** | «Кольцо обручальное гладкое, золото 585» — то, что видит покупатель; под моделью объединяются одинаковые бирки (разные размеры) | собирается правилом из бирок |
| **Салон** | Точка AURA в городе (Раменское, Ногинск, …) | 1С-магазин, сопоставленный с салоном сайта |
| **Витрина** | Отдельная «полка» данных **только для сайта** (без телефонов клиентов, без внутренних сумм) | новый модуль в конвейере BizHub |
| **Ручной слой** | Данные, которых в 1С нет и не будет: красивое название, описание, фото, отзывы | заполняется вами/нами один раз, обновления 1С его не трогают |

## 3. Схема карточки товара: какое поле откуда берётся

Таблица ниже — «рецепт» каждой карточки. Отметки: ✅1С — автоматически из выгрузки;
⚙️Правило — собирается алгоритмом (настраивается один раз, проверяется на выборке);
✍️Ручной слой — заполняется один раз (можно начать с пустым/черновиком);
⏳Позже — не делаем в Уровне 1.

| Поле карточки | Пример | Источник |
|---|---|---|
| Название | «Кольцо обручальное гладкое» | ⚙️ из имени 1С «кольцо обр глк к-959» + ✍️ красивое имя (черновик) |
| Категория | Кольца → Обручальные | ⚙️ тип изделия 1С + правила по названию |
| Артикул | 000081080 | ✅1С |
| Металл / проба | Золото 585 | ✅1С (в имени «(Au.585)» / характеристики) |
| Вес | 2,84 г | ✅1С (по бирке; где пусто — не показываем) |
| Камень / вставка | Бриллиант / без вставки | ⚙️ из характеристики 1С («др/к, бриллиант…») |
| Размеры | 15–20 (пилюли) | ⚙️ из бирок (razmer) — проверим глубину на этапе B |
| Цена | 18 900 ₽ | ✅1С: доизвлекаем «розничную цену» из полного файла (регистр цен); запасной вариант — цена последних продаж / партии (см. §7) |
| Наличие по салонам | «Раменское — 13 шт, Ногинск — 14 шт, Озёры — 14 шт» | ✅1С: остатки по магазинам на дату выгрузки |
| Фото | — | ⏳ ручной слой (заглушка «фото скоро») |
| Описание, «Паспорт украшения» текст | — | ✍️ частично из ✅1С (металл/вес/камень), тексты ухода — ручной слой |

## 4. Живой пример: что реально лежит в вашей выгрузке

Вот настоящие товары из вашей 1С (считано из `warehouse.db`/`warehouse_agg.db`,
остатки на 07.09.2026 — дату выгрузки). Это **не** демо-данные.

**Пример 1. Кольцо обручальное гладкое, золото 585** (в 1С: «кольцо обр глк к-959 (Au.585)»)

| Салон | В наличии |
|---|---|
| Маг №4 Луховицы | 15 шт |
| Маг№11 Ногинск №3 | 14 шт |
| Маг №5 Озёры | 14 шт |
| Маг №1 Раменское №1 | 13 шт |
| Маг№15 Егорьевск №2 | 13 шт |
| Маг№14 Электрогорск | 12 шт |
| Маг№18 (Подружка) | 10 шт |
| Маг№12 Воскресенск №2 | 8 шт |
| **Итого по сети** | **~104 шт** (служебный «склад брака» — сайту не показываем) |

**Пример 2. Цепь, золото 585** (в 1С: «цепь нц12-200 (Au.585)») — в наличии 20/17/15/13/12/10/9/9 шт
по Раменское/Ногинск/Подружка/Луховицы/Озёры/Егорьевск/Электрогорск/Воскресенск.

**Пример 3. Браслет, золото 585** (в 1С: «браслет нб12-200 (Au.585)») — 11/11/10/10/8/8/8/7 шт
по Электрогорск/Ногинск/Озёры/Раменское/Воскресенск/Подружка/Егорьевск/Луховицы.

> Выводы из живых данных:
> 1. **Наличие по салонам — есть**, считанное по всей сети, в штуках. Именно его покажем
>    как «В наличии в салоне (город)» — ключевая фишка AURA.
> 2. Имена в 1С технические («обр глк к-959») — для клиента переводим: «обр» → обручальное,
>    «глк» → гладкое и т.п. Словарик правил создаётся один раз.
> 3. Есть точки вне городов AURA (например «Маг№18 Подружка») — на этапе 0 утверждаем,
>    какие магазины 1С = какие салоны на сайте (таблица соответствия, см. §9).
> 4. Часть записей — не украшения (футляры, «подарок шоколад», подвески-сувениры, металл).
>    Правило «что показываем»: только ювелирные изделия (кольца/серьги/браслеты/цепи/подвески/
>    колье), без служебных товаров — настраивается и проверяется на цифрах.

## 5. Как «билки» превращаются в «товар-модель» (правило, которое настроим)

В 1С одно украшение = запись со своим кодом (примеры выше: «кольцо обр глк к-959» — таких бирок
104 шт по сети, у каждой свой штрихкод/размер/вес). Для сайта нужен один товар с вариантами.
Правило группировки (настраивается один раз и проверяется):

```
бирки с одинаковым [название без размера] + [металл/проба]  →  один товар-модель
    товар «Кольцо обручальное гладкое, Au 585»
        варианты: размер 16 (в Раменском — есть), размер 17 (в Ногинске — есть)…
```

Наличие «в салоне» считаем по биркам модели в этом салоне. Если размеров в данных нет
(часть позиций без размера, например цепи по длине) — товар показываем без пилюль размера.
Где группировка сомнительна (одинаковые имена у разных ref — видели в данных), правило
объединяет их в один товар — это правильно для витрины (см. §7, контроль качества).

## 6. Страницы AURA → что на них станет живым

| Страница макета | Что станет динамическим (из витрины) |
|---|---|
| Главная | Хиты (по продажам из 1С), Новинки (по дате поступления), категории с количеством |
| Каталог + категории | Сетка товаров, счётчики («Кольца — 1 240»), фильтры, сортировка, «в наличии в моём городе» |
| Карточка товара | Цена, металл/проба/вес/камень, размеры, «Паспорт» (что есть в 1С), блок «Забрать в салоне (город)» с реальным наличием, кнопки корзины/резерва |
| Свадьба | Подборка обручальных/помолвочных (правило по типу изделия) |
| Акции | Сначала — заглушка «акции скоро» (источник акций уточняем, §7) либо скидочные бейджи из 1С, если найдём |
| Свой салон рядом | Страницы салонов: адрес, часы, телефон (справочник, ручной слой), «украшения, которые можно забрать здесь» — реальное наличие |
| Поиск | По названию/артикулу/категории по витрине |
| Корзина → Оформление | Настоящая корзина; оформление = «самовывоз из салона» + телефон клиента |

## 7. Честные ограничения и как с ними работаем

1. **Цена «на сегодня».** В извлечённой аналитической базе цены — из чеков продаж и стоимости
   партий. Для витрины нужна «розничная цена». План: из того же полного файла выгрузки доизвлечь
   справочник/регистр цен (в конфигурации он есть — «ТипыЦенНоменклатуры»), наш инструментарий
   это умеет. Если в конкретной базе цен нет — запасной вариант: цена по последним продажам
   модели (с пометкой «цена от»). Решение примем на этапе A по факту данных, покажем вам пример.
2. **Качество имён и атрибутов.** Часть характеристик в 1С заполнена неединообразно.
   Витрина показывает **только достоверное** (пустые поля не рисуем — сайт обещает «честный паспорт»).
   На этапе A сделаем «контрольную выборку»: N реальных товаров → вы посмотрите, что получилось.
3. **Фото** — отдельный ручной слой, откладываем (вы подтвердили). Пока на карточках — аккуратная
   заглушка «фотография скоро появится».
4. **Акции/скидки** — в Уровне 1 не обещаем; если в выгрузке найдётся признак скидок — покажем.
5. **Остатки** актуальны на дату последней выгрузки (вы приносите флешку — данные свежие).
   Показываем дату актуальности («Остатки на 07.09.2026») — честно и понятно клиенту.
6. **Размеры** — глубина данных по размерам проверится на этапе B; где размеров нет — товар
   без пилюль (как цепи/браслеты по длине).

## 8. Заказ на самовывоз (что происходит с корзиной)

1. Клиент добавляет товар в корзину → оформление (4 шага из макета): телефон → **салон
   самовывоза** (город/адрес) → подтверждение → «Спасибо, ждите СМС/звонок».
2. Заказ **сохраняется в базе заказов сайта** (на ПК рядом с витриной): товары, размеры, салон,
   телефон, дата/время.
3. Вы видите заказ в разделе «Заказы» (мини-админка сайта, защищена паролем): список новых,
   отметка «перезвонили клиенту», «товар отложен в салоне». По желанию — дублирование заказа
   письмом на e-mail или в Telegram салона.
4. В 1С ничего не создаётся (это Уровень 3, когда появятся заказы в 1С).
5. Клиент забирает и оплачивает в салоне как обычно (наличные/карта в кассе 1С).

## 9. Что нужно утвердить до/в начале сборки (минимум)

1. **Салон ← магазин 1С.** По вашим городам утверждаем таблицу соответствия (пример для проверки):

   | Город AURA | Магазин(ы) в 1С (из выгрузки) |
   |---|---|
   | Раменское | Маг №1 Раменское №1 (+ №2/№3, если открыты) |
   | Жуковский | Маг №9 Жуковский 2 |
   | Ногинск | Маг №8 Ног №1, Маг№11 Ногинск №3 |
   | Воскресенск | Маг №3/№12/№13 Воскресенск (открытые) |
   | Егорьевск | Маг №7 Егорьевск №1, Маг№15 Егорьевск №2 |
   | Луховицы | Маг №4 Луховицы |
   | Озёры | Маг №5 Озёры |
   | Электрогорск | Маг№14 Электрогорск |
   | ? | «Маг№18 Подружка», Подольск, Солнечногорск, Истра, Саларис — показывать? |

   (точный список открытых/закрытых уточним по данным и покажем вам)
2. **Что показываем:** только украшения; служебное (футляры, сувениры, металл) исключаем —
   покажем вам контрольные цифры «сколько моделей попало в каталог».
3. **Контакты салонов** (адрес, часы, телефон для страниц «Свой салон рядом») — есть в данных
   частично; сверим и дополним с вами (ручной слой).
4. **Названия-«переводы»**: словарик «обр→обручальное, глк→гладкое, с/к→с камнем…» — черновик
   сделаем мы, вы поправите.

## 10. Порядок работ и что вы получите после каждого шага

| Шаг | Работа | Вы увидите |
|---|---|---|
| **A. Контрольная выборка** | Правила «модель=товар», категории, металл/проба, исключение служебного; доизвлечение цен | Таблицу «500–2000 реальных товаров: название, категория, металл, цена, наличие по салонам» — **до написания сайта**, на утверждение |
| **B. Витрина + API** | Модуль витрины в конвейере BizHub + API + обновление с флешки (ярлык) | Обновление «вставил флешку → запустил → свежие данные» |
| **C. Живые страницы** | Каталог/карточка/главная/салоны/поиск на реальных данных, заглушки фото | Сайт с настоящим каталогом (локально на ПК) |
| **D. Корзина + заказ на самовывоз** | Корзина, оформление, база заказов, раздел «Заказы» для вас | Полный цикл «клиент заказал — вы увидели» |
| **E. Полировка** | Фильтры, «в наличии в моём городе», дата актуальности, скорость | Готово к показу клиентам |
| **F. (потом) На хостинг** | Переезд на ваш хостинг/домен (архитектура готова) | AURA.RU в интернете |

**Первый контроль качества** — Шаг A: вы утверждаете данные (товары/цены/наличие) ДО того,
как мы их показываем на сайте. Это снимает главный риск «данные из 1С оказались не такими».

- **API** `server/api.py` (http://127.0.0.1:8138): `/api/meta`, `/api/salons`, `/api/categories`,
  `/api/products` (фильтры: категория, металл, город, поиск, цена; сортировки), `/api/products/<id>`
  (карточка с наличием по городам).
- Файлы запуска: `server/build_catalog.bat`, `server/start_api.bat`; README в `server/README.md`.
- **Цена в витрине сейчас = цена последней продажи** (промежуточно). В полном файле 1С найден
  регистр **«ЦеныНоменклатуры»** (`_InfoRg6736`) — финальная «цена на сегодня» будет из него
  (следующий шаг этапа B), а также размеры и слой красивых названий.
- Дальше по плану: этап C — «оживление» страниц AURA (каталог/карточка/главная/салоны) данными API;
  этап D — корзина и заказ на самовывоз.
