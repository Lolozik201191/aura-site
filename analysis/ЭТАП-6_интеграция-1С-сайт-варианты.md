# ЭТАП 6. Интеграция 1С с сайтом AURA — варианты и план

> Для кого: руководитель/владелец, не программист.
> Что уже есть: (1) проект BizHub — полный разбор выгрузки 1С «ЮТД ред.10.5»
> (ювелирная розница + ломбард, ~20 магазинов в Московской обл.) в SQLite-хранилище
> с ежедневным обновлением; (2) сайт AURA — готовый дизайн-макет (статичные HTML-страницы
> с демо-данными: каталог, карточка товара, «свой салон рядом», личный кабинет и т.д.).
> Задача: соединить их — чтобы каталог, цены, наличие, клиенты и заказы на сайте
> жили из данных 1С и обновлялись каждый день (выгрузка приходит ежедневно).

> **Статус обсуждения (зафиксировано):** платформа сайта — «оставляем дизайн AURA,
> добавляем серверную часть» (Вариант 1, «своя труба»); реализацию пока не начинаем —
> документ обсуждается. Вопросы: фото товаров, цены «на сегодня», стартовый ассортимент —
> открыты.

> **Решения по обсуждению (2026, ЭТАП 6):**
> 1. Ежедневная выгрузка приходит **на флешке** (полная выгрузка с сервера 1С) — обновление
>    делаем по механизму BizHub `refresh_data.bat`, без «живого» доступа к 1С.
> 2. **1С-специалиста нет** → строим только на данных выгрузки, без доработок в 1С
>    (регистр цен при необходимости доизвлекаем из полного файла нашим инструментарием).
> 3. Цель первого шага — **каталог-витрина**: показать клиентам; заказ — звонком или в салон
>    (без онлайн-оплаты и без создания заказов в 1С).
> 4. Фото товаров — **отложено**, варианты наполнения рассмотрим позже.
> Проверено по данным: движения по биркам (приход/расход, магазин, вес, стоимость, дата до
> последнего дня выгрузки) есть → «наличие по салонам» из выгрузки строится.

> **Решения по Шагу A (контрольная выборка, см. `ЭТАП-6.1` и папку `ШагA-контрольная-выборка/`):**
> - На сайте — **7 городов AURA: Раменское, Ногинск, Воскресенск, Егорьевск, Луховицы, Озёры,
>   Электрогорск. Жуковский закрыт** (поэтому его нет в остатках 1С). Точки вне этих городов
>   (Подружка, Подольск, Солнечногорск, Истра, Саларис) на сайте **не показываем**.
> - Контрольная выборка: 18 067 ювелирных моделей в наличии; правила и файлы готовы,
>   ожидаются правки заказчика по категориям/названиям.
> - Переходим к этапу B: витрина + API + розничные цены из полного файла выгрузки.

1. **Данные для сайта уже почти все есть в 1С** — мы их извлекли и проверили в проекте BizHub:
   товары (111 тыс. номенклатурных позиций), характеристики (металл, проба, камень, размер),
   партии с бирками/штрихкодами, продажи по чекам, остатки по магазинам, дисконтные карты
   с телефонами клиентов, бонусы, скупка. Города салонов AURA (Раменское, Жуковский, Ногинск,
   Воскресенск, Егорьевск, Луховицы, Озёры, Электрогорск) — это **те же магазины, что лежат в 1С**.
2. **Сайт пока — «картинка», а не магазин.** Чтобы он «ожил», нужен бэкенд (серверная часть):
   сейчас страницы HTML с демо-товарами и демо-клиентами, базы данных и приёма заказов нет.
3. **Предлагаю три уровня интеграции** (можно делать по очереди):
   - **Уровень 1 — «Каталог с 1С на сайт»** (нужен всем, даёт 80 % ценности):
     товары, цены, скидки, наличие по салонам обновляются автоматически раз в сутки.
   - **Уровень 2 — «Клиенты и личный кабинет»**: вход по телефону → сайт находит клиента
     в 1С по карте лояльности: бонусы, «мои покупки», цифровые паспорта украшений.
   - **Уровень 3 — «Заказы и резервы с сайта в 1С»**: заказ/резерв/запись на примерку
     с сайта автоматически создаются в 1С и отслеживаются по статусам.
4. **Рекомендация:** начать с Уровня 1 «по-своему» (без покупки новой CMS): достроить уже
   работающий конвейер BizHub до «витрины для сайта» и отдать её сайту через простой API.
   Это самый быстрый и дешёвый путь от макета к живому каталогу. Уровни 2–3 — следующим шагом,
   после решения по платформе сайта.

## 3. Что такое «интеграция» на практике (по-простому)

Ежедневно (ночью) 1С-данные должны попадать на сайт, а действия покупателей на сайте
(заказ, резерв) — обратно в 1С. Технически это делается одним из способов:

```
Способ A. «Через файл»      : 1С → файл (как сейчас .1CD) → программа перекладывает → сайт
Способ B. «Через API»       : 1С/хранилище → сервер отдаёт данные по адресу → сайт забирает
Способ C. «Двусторонний обмен»: 1С и сайт общаются напрямую (заказы и туда, и обратно)
```

У вас уже фактически построен **Способ A/B в одну сторону**: BizHub каждую ночь читает
свежую выгрузку 1С и пересобирает базу. Осталось «продлить трубу» до сайта.

## 4. Варианты интеграции (сравнение)

### Вариант 1. «Своя труба» — достроить BizHub до витрины сайта (рекомендую для старта)

Как работает: к существующему конвейеру добавляется модуль «витрина для сайта»:
отбирает из warehouse.db **только то, что можно показывать публично** (товар, цена, остаток,
характеристики — без ФИО/телефонов), и публикует через простой API. Сайт (HTML/JS) делает
запросы и рисует каталог, фильтры, наличие, карточку.

- ✅ Самый быстрый путь: конвейер, обновление, расписание уже есть.
- ✅ Не нужно покупать новую платформу и переделывать дизайн AURA.
- ✅ Данные обновляются автоматически «как ляжет выгрузка» (ночной прогон).
- ✅ Дешево: тот же стек (Python/SQLite), тот же сервер.
- ⚠️ Каталог и наличие — да; полноценные заказы/оплата/ЛК — потребуют написать бэкенд
  (это нормальная работа, но её не «включить галочкой»).
- ⚠️ Фото всё равно нужно завести отдельно.

### Вариант 2. Готовый интернет-магазин + штатный обмен с 1С

Как работает: сайт переезжает с HTML-макетов на «коробочную» платформу, у которой есть
**встроенный обмен с 1С по стандарту** (так делают почти все ювелирные сети РФ):
- **1С-Битрикс: Управление сайтом** — самый типовой для ювелирки: каталог, корзина, ЛК,
  заказы «из коробки»; обмен с 1С (товары/цены/остатки/заказы) — штатная функция.
- Либо WordPress/WooCommerce, CS-Cart и др. + модуль обмена 1С (есть готовые).

- ✅ Меньше «своей» разработки для магазина: каталог/корзина/оплата/ЛК — типовые.
- ✅ Двусторонний обмен с 1С решается штатно (в т.ч. заказы).
- ⚠️ Дизайн AURA придётся перенести на платформу (готовые макеты — помощь, но не 1-в-1).
- ⚠️ Платные лицензии/хостинг (у Битрикса — существенные).
- ⚠️ Обмен «в лоб» с 1С обычно всё равно требует 1–2 недели настройки у 1С-специалиста.

### Вариант 3. Полный «самописный» магазин с прямым обменом в 1С

Как работает: свой бэкенд сайта + публикация HTTP-сервисов в самой 1С (пишет 1С-программист);
сайт создаёт в 1С заказы/резервы и читает статусы.

- ✅ Максимально «под вас», дизайн сохраняется.
- ❌ Самый дорогой и долгий; нужен и разработчик сайта, и 1С-программист с доступом к конфигурации.
- ❌ Для старта избыточно.

### Сравнение в одной таблице

| Критерий | 1. Своя труба (реком.) | 2. Готовая платформа | 3. Всё своё |
|---|---|---|---|
| Скорость до «живого каталога» | **недели** | 1–2 мес. | 3+ мес. |
| Стоимость | низкая | средняя (лицензии) | высокая |
| Каталог+цены+остатки с 1С | ✅ | ✅ | ✅ |
| Личный кабинет с бонусами 1С | Уровень 2 (доп. работа) | ✅ штатно | ✅ |
| Заказы с сайта в 1С | Уровень 3 (доп. работа) | ✅ штатно | ✅ |
| Дизайн AURA как в макетах | ✅ сохраняется | перенос | ✅ |
| Нужен ли 1С-программист | почти нет (Ур.3 — да) | да, на настройку обмена | да, постоянно |
| Риски | минимальные | средние | высокие |

> **Мой совет:** сделать **Вариант 1 → Уровень 1** сейчас (быстрый живой каталог,
> «потрогать» и убедиться в данных), а параллельно решить по платформе: если бизнесу нужны
> заказы-онлайн, оплата и ЛК «как у федералов» — через полгода перейти на Вариант 2,
> а наработки Уровня 1 (маппинги, фото, чистка данных) перенесутся туда без потерь.

## 5. Уровни интеграции по разделам сайта (что и в каком порядке)

### Уровень 1. Каталог, цены, наличие (1С → сайт, односторонне)

Разделы сайта: **Каталог** (все категории), **Карточка товара**, **Фильтры**, **Поиск**,
**Главная** (хиты/новинки), **Свадьба**, **Акции**, **«В наличии в моём городе»**.

Что делаем:
1. Сопоставляем номенклатуру 1С с категориями сайта AURA (кольца/серьги/браслеты/колье/
   подвески/цепи/комплекты) — по типам изделий 1С + правила по названию. Один раз настраиваем,
   дальше автоматом.
2. Из характеристик собираем «паспортные» поля карточки: металл, проба (585/750/925), вес,
   вставка (бриллиант/камень), размер. Что-то в 1С заполнено не везде — помечаем «уточнить»,
   показываем только достоверное (сайт обещает «честный паспорт» — пустых полей не показываем).
3. Цены и скидки: источник «цена сегодня» + акции (уточнить у 1С, см. §2).
4. Наличие: остаток по каждому салону → «В наличии в салоне Раменского», «Привезём за 2 дня».
   Закрытые магазины из выгрузки сайту не показываем (в 1С они помечены «закрыт»).
5. Фото: заводим каталог изображений «артикул → фото» (сток/съёмка), привязка — по артикулу.
6. Расписание: ночью конвейер обновляет витрину; утром сайт уже показывает свежие цены/остатки.

Результат: сайт = живой каталог сети, обновляемый ежедневно, «3 клика до покупки» как в макете
(покупка пока — заказ звонком/в салон, либо переходим к Уровню 3).

### Уровень 2. Клиенты и личный кабинет (1С → сайт, односторонне + вход)

Разделы сайта: **Вход по телефону**, **Личный кабинет**: бонусы, «мои покупки», «мои украшения
(паспорта)», повтор заказа.

Что делаем:
1. Вход по номеру телефона (СМС-код — обычный сервис). По номеру ищем клиента в 1С
   (в картах лояльности ~90 тыс. клиентов с телефонами).
2. Показываем: баланс бонусов AURA, историю покупок (по чекам, привязанным к карте),
   купленные изделия → «Мои украшения» с паспортами и гарантией (паспорт из характеристик +
   серийный номер бирки), скидки по карте.
3. Ограничение честности: по чеку в 1С не всегда есть телефон (покупали «без карты») —
   тогда «паспорт» появится, если клиент привяжет чек/бирку в салоне. Это надо проговорить.
4. Новые клиенты, зарегистрированные на сайте, приходят в 1С (Уровень 3 или выгрузкой).

Результат: ЛК из макета работает на реальных данных — бонусы, покупки, паспорта.

### Уровень 3. Заказы, резервы, примерки (сайт → 1С, двусторонне)

Разделы сайта: **Корзина → Оформление заказа**, **«Зарезервировать в салоне»**,
**«Записаться на примерку»**, статусы заказов в ЛК, **«Обмен старого золота»** (заявка → в скупку 1С).

Что делаем (это уже требует работы 1С-программиста или готовой платформы):
1. С сайта в 1С создаются документы: заказ/резерв (с товаром, размером, салоном), заявка на скупку.
2. Из 1С на сайт возвращаются статусы: принят → собран → в салоне → выдан; при резерве —
   подтверждение и срок готовности (как в сценариях макета).
3. Оплата: онлайн (карта/СБП) — платёжный шлюз, деньги сверяются с 1С по документам оплат
   (структура оплат в 1С уже разобрана в BizHub).
4. Сервис: «Сервисная заявка» по паспорту (из ЛК) — тоже документ в 1С (Уровень 2+).

Результат: полный цикл «онлайн + салон» из концепции AURA: резерв → примерка → покупка в салоне,
заказ с доставкой, обмен старого золота онлайн.

## 6. Ежедневное обновление (как это будет жить)

У вас выгрузка 1С приходит каждый день. Уже есть готовый механизм (`refresh_data.bat` в BizHub):
бэкап → разбор свежего файла 1С → пересборка баз → проверки. План на «ежедневность»:

1. Ночью (например, 03:00) планировщик Windows запускает обновление.
2. Конвейер проверяет: пришёл ли новый файл выгрузки; если да — обновляет хранилище,
   если нет — оставляет вчерашние данные (сайт не «падает», просто данные вчерашние).
3. Отдельным шагом собирается публичная витрина сайта (без внутренних данных).
4. Утром сайт показывает свежие цены/остатки/новинки. Журнал обновлений и оповещение
   об ошибке — чтобы «тихо не сломалось» (в BizHub это уже есть).

## 7. Белые пятна и вопросы, которые надо решить вместе (для обсуждения)

1. **Боевая 1С.** Та ли это база «ЮТД ред.10.5», из которой идёт ежедневная выгрузка?
   Где лежит свежий файл? Есть ли доступ к серверу 1С и возможность 1С-программисту
   что-то доработать (для Уровня 3)?
2. **Цены и акции.** Какой источник «цены сегодня» и «акции» в боевой 1С (регистр цен)?
   Нужно, чтобы сайт показывал актуальную цену, а не «последнюю из чеков».
3. **Фото товара.** Готовы ли делать предметную съёмку/закупать сток? Сколько позиций
   каталога реально выводим на сайт на старте (500? 5 000?) — от этого зависит объём фото.
4. **Платформа сайта.** Оставляем «свою трубу» на HTML+JS (Вариант 1) или планируется
   переход на готовую платформу (Вариант 2)? Домен и хостинг уже есть?
5. **Какие магазины на сайте.** Все открытые точки или только 8 городов из макета
   (в 1С есть ещё Подольск, Солнечногорск, Истра, Москва-Саларис и закрытые точки)?
6. **ПДн.** На сайте нельзя показывать внутренние данные (ФИО/телефоны клиентов, обороты).
   Витрина каталога — публичная, ЛК — только после входа. Это закладываем в архитектуру сразу.
7. **Стартовый ассортимент.** Ювелирные изделия в 1С часто заводятся «под партию»
   (десятки тысяч бирок). Для сайта нужен «товарный каталог» (модель), а не каждая бирка:
   настраиваем правило «модель = товар, бирки/размеры = варианты». Это ключевая настройка Уровня 1.

## 8. Предлагаемый план работ (этапы)

| Этап | Что делаем | Результат | Примерно |
|---|---|---|---|
| **0. Решения** | Ответы на вопросы §7 (источник выгрузки, цены, фото, города) | Согласованная схема | 1 неделя |
| **1. Витрина каталога** | Модуль «товар для сайта»: модель + характеристики + цены + остатки по салонам + API | Живой каталог AURA на реальных данных | 2–3 недели |
| **2. Фото и полировка каталога** | Фото по артикулам, категории, «хиты/новинки», SEO | Каталог «как в макете», но настоящий | 2–4 недели (параллельно с фото) |
| **3. Наличие и салоны** | Страницы «Свой салон рядом» на реальных остатках и адресах | Резерв «в салоне» (по телефону/заявке) | 1–2 недели |
| **4. Личный кабинет** | Вход по телефону, бонусы, мои покупки, паспорта | ЛК на реальных данных клиентов | 2–3 недели |
| **5. Заказы в 1С** (если выбрана своя платформа) | Создание заказов/резервов в 1С, статусы, оплата | Полный онлайн-магазин + салоны | 1–2 мес. (с 1С-специалистом) |

Итог пути: сайт AURA превращается в **живой витринный каталог сети** (этапы 1–3),
затем — в **полноценный интернет-магазин с личным кабинетом**, где 1С — единый источник
правды: товары, цены, остатки, клиенты, заказы; обновление — ежедневное и автоматическое.
