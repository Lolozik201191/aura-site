# AURA — сервер витрины (этапы B–C)

Сервер отдаёт **копию дизайн-макетов AURA** (`../site/` — те же страницы и стили, что в `mockups/`)
и **встраивает в них реальные данные из 1С** через JSON API. Дизайн не переделывается:
`../site/` — это копия `../mockups/` + маленький скрипт `site/assets/live.js`, который заменяет
демо-данные на реальные (если API недоступен — страницы остаются демо, ничего не ломается).

## Запуск (ПК с данными BizHub)

1. `build_catalog.bat` — пересобрать витрину (после новой выгрузки 1С с флешки).
2. `start_api.bat` — поднять сервер: http://127.0.0.1:8138
3. Проверка:
   - `http://127.0.0.1:8138/catalog.html` — каталог «Кольца» на реальных товарах;
   - `http://127.0.0.1:8138/product.html?id=2` — реальная карточка товара;
   - `http://127.0.0.1:8138/api/meta` — служебное (дата данных, число товаров).

Обновление: вставили флешку → обновление BizHub → `build_catalog.bat` → данные на сайте свежие.

## Что уже на реальных данных (без изменения дизайна)
- Главная: «Хиты» и «Новинки», счётчики категорий на плитках;
- Каталог: товары, цены, наличие «в салоне Раменского · сегодня / привезём за 2 дня»,
  категории по ссылке `catalog.html?cat=Серьги` (и др.), фильтры металл/город/цена;
- Карточка товара: название, артикул 1С, металл/проба, цена, «Забрать в салоне»;
- «Свой салон рядом» (`salon.html?city=…`): заголовок города и лента «можно забрать сегодня»;
- Корзина → **заказ на самовывоз**: реальные позиции, итог, имя/телефон → заявка сохраняется
  (`data/orders.json`), видна на `orders.html` (код доступа `aura2026`). В 1С ничего не создаётся;
- Список заказов: `orders.html` — служебная страница для сотрудников.

## Что дальше (в том же дизайне)
- Главная — баннеры/акции; раздел «Свадьба» (обручальные — реальные);
- Розничные цены из регистра «ЦеныНоменклатуры» полного файла (сейчас — цена последней продажи);
- Фото товаров — отдельно (в 1С их нет).

## Оригиналы макетов
`../mockups/` не изменяются (эталон дизайна). Рабочая копия сайта — `../site/`.
